# Omoikane — agent operating manual

You maintain this wiki. The human curates sources and asks questions; you write every page under `wiki/`.

## Layout

- `raw/inbox/` — sources waiting for ingest. Read only.
- `raw/sources/` — ingested sources. Immutable. Never edit, never delete.
- `raw/assets/` — images downloaded by Obsidian. Read only.
- `wiki/sources/` — one page per ingested source.
- `wiki/entities/` — people, organisations, products, places.
- `wiki/concepts/` — ideas, methods, recurring themes, comparisons.
- `wiki/queries/` — filed answers to questions.
- `index.md` — generated by `python bin/wiki-index.py`. Never edit by hand.
- `log.md` — append-only chronology. Prefix every entry `## [YYYY-MM-DD] <op> | <title>`.
- `_review.md` — questions for the human: contradictions, ambiguous claims, missing sources.

## Page contract

Every page under `wiki/` starts with this frontmatter; `wiki-index.py` and `wiki-lint.py` depend on it:

```yaml
---
title: Exact page title
type: source | entity | concept | query
summary: One line, under 120 characters, used verbatim in index.md
tags: [tag-a, tag-b]
created: YYYY-MM-DD                 # when this wiki page was written, not the source
updated: YYYY-MM-DD
dated: YYYY-MM-DD                   # source pages only: the date the source itself bears, or unknown
sources: [wiki/sources/<slug>.md]   # pages this one draws from; empty list on source pages
---
```

- Filename is the kebab-case slug of `title`.
- Link pages with `[[slug]]` wikilinks. A claim taken from a source cites it inline: `(source: [[slug]])`.
- One entity or concept per page. A concept mentioned on three pages gets its own page.
- A contradiction lives where its two sides meet: on the source page when a source contradicts itself, on the entity or concept page when two sources disagree. Keep both claims under `## Contradictions`, add an entry to `_review.md`, and do not pick a winner.

## Operations

Prompts live in `prompts/`; each is reachable as a slash command in Claude Code and OpenCode.

- Ingest a source: `prompts/ingest.md`.
- Answer a question and file it: `prompts/ask.md`.
- Semantic health check: `prompts/lint.md`.

After any operation that touches `wiki/`, finish with:

```
python bin/wiki-index.py
python bin/wiki-lint.py
```

`wiki-lint.py` exits non-zero on broken wikilinks, missing frontmatter, undated source pages or orphan pages. Fix every finding before you report done.

## Domain

This wiki is the knowledge base of the harness-bench research project (a *projeto de pesquisa* for the Metodologia Científica course; "PCC" is only the repo shorthand, the work is not a Projeto de Conclusão de Curso): agent-harness cost vs performance with the language model held fixed. Since 2026-09-14 the experiment builds the same SaaS, Finn (https://github.com/YuukiFST/Finn, issues #1-#22), twice from scratch, once with OpenCode and once with pi, each arm from the same frozen specification in nine units, and compares the tokens each harness spends per construction (paired per unit); harness zero, oh-my-pi, DeepSWE, and the ticket-by-ticket design with author-written reference states belong to previous designs and are not to be reintroduced.

- Emphasise when ingesting: harness definition and components, cost/performance numbers with model held fixed (Succ/Mtok, pass@1, tokens, deltas atribuiveis ao harness), measurement method (proxy vs self-report), model-specificity/inversion, open gaps (attribution, oracle adequacy).
- Every quantitative claim keeps its denominator: model, harness, benchmark, n runs, date measured.
- Preprints are labelled `*Preprint*, nao revisado por pares` unless the source page records a venue.
- Portuguese pages keep English technical terms (harness, scaffold, proxy, oracle) in italics as in `dist/projeto-pcc.docx`.
- Glossary authority: `CONTEXT.md` for arm, tier, product, specification, unit, initial workspace, acceptance test, construction, cell, step, fixed load, concluded/unconcluded/tampered unit, discarded construction, pilot unit.
- Finn's product decisions live in its issues; `wiki/entities/finn.md` summarises them. A Finn claim cites the issue number.

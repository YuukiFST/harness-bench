Justificativa, tema, problema, objetivo geral

Justificativa · quem paga é o desenvolvedor, na assinatura, e a empresa, em escala. As comparações publicadas contrastam equipes diferentes e não dizem qual decisão de projeto pesa.
Tema · a escolha do harness como decisão de engenharia: efeito sobre custo por tarefa concluída e taxa de sucesso, modelo fixo.
Problema · com o modelo já escolhido, quanto do custo e do sucesso vem do harness? Quais decisões de projeto explicam a diferença?
Objetivo geral · medir esse efeito, isolar decisões pela comparação harness × fork direto, entregar critério de escolha reproduzível.

Sete objetivos específicos

  • 1 Instrumento externo: requisições, tokens, latência
  • 2 Suíte com objetivos numerados e oracle próprio
  • 3 Harness zero em laço ReAct (controle)
  • 4 Mesma suíte, mesmo modelo, todos os braços, com repetição
  • 5 Segundo modelo: a ordenação se mantém ou inverte?
  • 6 Custo relatado × custo medido no proxy
  • 7 Publicar runner, dados e scripts, custo zero

Hipóteses

H1 · entre harnesses distintos no mesmo modelo, a diferença de custo por tarefa é relevante para quem paga, comparável a trocar de modelo. Refutada se os intervalos de Succ/Mtok se sobrepuserem em toda a suíte.
H2 · a diferença persiste entre um harness e seu fork direto: decisões isoláveis, não acúmulo de bases distintas. Refutada se pi e oh-my-pi não diferirem em Succ/Mtok.
Camada 1, medição própria: primeira requisição da mesma tarefa, endpoint simulado, n = 1 (determinístico), tokenizador cl100k_base, 28 ago. 2026. pi 0.80.10, oh-my-pi 17.2.10.

Duas camadas de medição→ alterna Camada 1 e Camada 2

Camada 1 · forma da requisição contra endpoint simulado. Esquemas, bytes de prompt, tokens por passo. Determinística, sem cota.
Camada 2 · desfecho das tarefas no modelo real via proxy reverso. Estocástica, consome cota, n ≥ 3.
O proxy conta tokens sobre os bytes transmitidos, um só tokenizador para todos os braços; o relatório do gateway fica para verificação cruzada.

Braços e matriz (braço × tarefa × nível)clique ou navegue com Tab em uma célula · cada célula recebe n ≥ 3 execuções após descartes

Célula: selecione.
Cada execução recebe uma classe · falhada: agente não cumpriu; é resultado, escore zero (estouro do relógio incluído). descartada: medição inconfiável; registrada, sem reparo nem repetição. Classe lida do registro do proxy.
Harness zero · controle. Laço observar/agir, 3 ferramentas, < 400 linhas de Python, sem planejamento, compactação ou retry.
Suíte · 8 tarefas Python do DeepSWE, fixadas por commit e SHA-256. Crédito parcial: fração de testes do verificador.
Limite único · relógio de parede 3× a mediana do harness zero nas tarefas-piloto. Sem teto de passos, já que o teto seria uma decisão de projeto do harness. Saída máxima idêntica via proxy.
DeepSWE (Huang et al., 2026): 113 tarefas, 91 repositórios; soluções de referência com 668 linhas em média, contra 32,8 no SWE-bench. Braços provisórios até os portões de confiabilidade.
